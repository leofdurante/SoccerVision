Pipeline — upload to read-out
1  Samplevideo_processor.extract_frames() — OpenCV, 5 fps, seeks to a requested window. Timestamps stay absolute (original video clock).
2  Detect + trackcv/tracker.py — one Ultralytics model.track() call: YOLOv8n (COCO person/sports ball) + ByteTrack, persist=True, imgsz=1280, conf=0.25.
3  FilterDetections rejected when their feet are off turf (HSV grass mask). Post-pass drops static-overlay tracks — long-lived + high in frame + near-zero movement.
4  Team splitcv/team_classifier.py — k-means over shirt-region colour on cached per-track crops, so a track gets one team, not a per-frame flicker.
5  Mapcv/field_mapper.py — cv2.getPerspectiveTransform. Currently identity-cornered, so it is a linear rescale, not a registration. See limits below.
6  Analyticsanalytics/ — width, depth, avg spacing, compactness, defensive line height, third occupancy, zone overloads, events.
7  Read-outservices/ai_analyst.py — Anthropic Messages API over the structured stats only, never frames. Deterministic rule-based fallback if the key is absent or the call fails.

Numbers we can defend
Detection6.0 → 12.3 players/frame. Lever was imgsz 640→1280, not the model — a player is ~30 px tall at native res. Cost: 21 → 72 ms/frame.
Ablation grid640/.40 = 6.0 · 640/.25 = 8.2 · 1280/.40 = 8.5 · 1280/.25 = 12.3
Tracking374 → 180 ids for ~22 players over 2 min. Median track 5 → 12 frames. Single-frame tracks 66 → 12.
Tracker sweep150 real frames. defaults 106 ids/659 det → tuned 55 ids/801 det. Winning config in cv/trackers/soccer_bytetrack.yaml.
Ball0 → 57 detections in a 2-min window — upscaling put it over the detector’s floor. Below 25 detections we withhold possession rather than print a number.
Throughput600 sampled frames (2 min of play) in ~60 s, CPU-only, no GPU in the loop.
Tracker config — and why each value
match_thresh0.8 → 0.95. Inter-frame displacement is only ~8% of a box height, so a missed match costs far more than a loose one.
fuse_scoretrue → false. Folding confidence into match cost penalises the weak-but-real detections that matter at this resolution — worth ~a third of tracked detections.
new_track_thresh0.25 → 0.6. A flicker now has to be genuinely confident before it becomes a new player. This is what stopped the id explosion.
track_buffer30 → 60. At 5 fps that is 12 s of tolerance, so a briefly occluded player keeps their identity.

The hard ones — answer these honestly
“Your homography is just a rescale. So the metrics are meaningless?” Agreed, as pitch coordinates — which is why we relabelled them camera-relative in the UI and withheld formation entirely. They still compare the two teams within one passage. We tested two fixes and rejected both with numbers: chained motion compensation drifts ~400 px in a 640 px frame; direct-to-reference loses overlap in 8 s (14 of 20 frames). Per-frame line detection fails because the match is on an American football field.
“180 identities for 22 players is still bad.” It is. IoU association is the ceiling — the fix is appearance embeddings, which is literally the re-ID bullet in the posting we targeted. What we can defend is the delta: 374 → 180 with the same detector, median track 5 → 12 frames, and a documented sweep behind it.
“Why 5 fps? You are throwing away temporal information.” Compute budget on CPU, and it is the parameter that broke tracking — ByteTrack’s defaults assume ~30 fps. Rather than raise fps we retuned the tracker for the sample rate we have. Raising it is the cheapest next win if a GPU is available.
“Why yolov8n and not a sports-specific detector?” No labelled sports data and no training budget in a hackathon, so we used COCO person off the shelf and spent the time on the parts we could measure. The ablation showed input resolution mattered far more than model size here — upscaling to 1280 beat every threshold change at 640.
“How do you know the extra detections at conf 0.25 are real players?” We do not, fully. We added a feet-on-turf test against an HSV grass mask, which removes people on the track and in the stands. Bench staff still pass, because they sit on turf beyond a touchline we cannot locate without registration — same missing capability as above.
“What is your evaluation? Any MOT metrics?” No MOTA/IDF1 — we have no ground-truth annotations, so reporting them would be fabricated. We used proxies we can actually compute: detections per frame, distinct ids per 100 samples, median track lifetime, single-frame track count, and detection-gap analysis. Building a small labelled slice is the honest next step.
Known limits — say these before they ask
• No pitch registration → all spatial metrics are camera-frame relative. • Identity churn: tracks average ~2.4 s. No re-ID. • Ball detection is sparse; possession is withheld under 25 detections. • Bench and sideline staff can still pass the surface filter. • Batch only — no live/streamed video. • Formation estimation is disabled; it needs real coordinates.
If a demo breaks
• Pitch view empty? The playhead is outside the analysed window — the overlay names the covered range. Scrub into it. • Video black? The annotated clip is H.264 now; if it stalls, switch the toggle to Original. • Insights say “rule-based”? The Anthropic call failed and fell back by design. The log line names the reason. • Uploading a full match? Pick a window several minutes in — broadcasts open with an intro package.
